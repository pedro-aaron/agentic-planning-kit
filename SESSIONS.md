# Sessions — the whole concurrency model

This is the normative concurrency document. It keeps planning local to each user, with one explicit
terminal reconciliation for the few shared planning artifacts.

## The rule

> **Per-user planning artifacts live under `.agentic_planning/<username>/`; shared `WORKSPACE_MAP.md`
> and pointers may be written by routes 1/3C/5, while the global README is regenerated by routes 0 and 5.**

Two people planning at the same time normally write no common file. Each feature's final step then
uses route 5 to reconcile `WORKSPACE_MAP.md`, managed entry-point pointers and the generated global
index. Those files are deliberately `exclusive`: the human scheduler serializes routes 0/5 in one
checkout. An external overlap is an ordinary Git conflict followed by a rerun; there is no lock,
queue, service or background orchestrator.

Everyone works on `main`. That is the intended way to use this kit.

## The username

The username is supplied by the human, in the `USER:` field that opens every trigger. It is
lowercase `[a-z0-9-]`, 2–32 characters, and it is a **directory name, not an account**. The kit
never validates it against a host, a remote, a commit author or a directory service, and never
derives it from one. Two people who pick the same username share a session directory and will
collide — that is their decision to make, and the kit will not police it.

The `USER:` field is the authority for a session. Routes 0/5 enumerate direct-child session paths to
regenerate the global navigation index, but route 5 writes status only in the invoking session; there
is no shared identity configuration.

## Layout

```text
.agentic_planning/
├── README.md                    # global index; its managed block is rebuilt by routes 0/5
└── <username>/                  # THE SESSION
    ├── SESSION.md               # who I am, what I am working on — this user's own index
    ├── _project_<slug>/
    │   ├── PROJECT_BLUEPRINT.md # ONE file, edited in place
    │   ├── DECISIONS.md         # ONE table, append-only
    │   └── F00/
    │       ├── FEATURE_F00.md
    │       ├── steps/NN-<slug>.md
    │       ├── TRIGGERS.md
    │       └── outputs/
    ├── _feature_<slug>/
    │   ├── FEATURE_<SLUG>.md
    │   ├── steps/NN-<slug>.md
    │   ├── TRIGGERS.md
    │   └── outputs/NN_<slug>.md
    └── _analysis_<slug>/ANALYSIS_<SLUG>.md

WORKSPACE_MAP.md                 # shared — see below
```

## Write scopes by route

| Route | Writes | Shared? |
|---|---|---|
| 0 · Open session | own `SESSION.md` + `.agentic_planning/README.md` managed index | **yes — exclusive** |
| 1 · INIT | `WORKSPACE_MAP.md` + managed pointer blocks | **yes** |
| 2 · Create feature | `.agentic_planning/<user>/_feature_<slug>/**` | no |
| 3 · New project | own project plan; at 3C, bootstrap map + pointers | **yes at 3C** |
| 4 · Analyze | `.agentic_planning/<user>/_analysis_<slug>/**` | no |
| 5 · Reconcile feature | `WORKSPACE_MAP.md`, managed pointers, `.agentic_planning/README.md`, own status | **yes — exclusive** |
| Step execution | product code + `<user>/…/outputs/` | **yes** (the code) |

## Shared artifacts and why

**`WORKSPACE_MAP.md`** describes the repository, not anyone's plan. Route 5 rechecks the facts a
feature affected and always keeps its close/index pointer current; `CLAUDE.md` / `AGENTS.md` only
carry the idempotent managed pointer blocks. These are shared Markdown files and stay `exclusive`.

**`.agentic_planning/README.md`** is the generated global index of all direct-child user sessions.
Only its `agentic-planning-index` block is managed; prose outside it survives. Every `SESSION.md`
remains canonical for that user's projects, features and analyses, so the README is navigation, not
a second ledger.

**Product code** is the case Git already exists for. Planning never touches product code; step
execution does, and two people executing steps that overlap resolve it the normal way. The
plan's disjoint write scopes exist to make that rare, not to replace Git when it happens.

## Global index and terminal reconciliation

Route 0 creates or refreshes the index when a user opens a session. Every normal feature plan includes one final join step; after
its gates and preliminary handoff, that step automatically runs route 5 before success. Route 5 verifies the handoffs,
updates affected map facts and pointers, flips only the invoker's row to `✅ Ejecutada`, then rebuilds
the README block deterministically by username. `✅ Ejecutada` means execution/reconciliation closed,
not manual acceptance. A failure leaves the feature unclosed; rerun route 5 after resolving the cause;
manual QA still happens only after a successful close.

## What the kit never does

It never runs `git`, initializes a repository, creates branches or worktrees, commits, pushes,
merges, rebases, resolves conflicts, reads commit identifiers, or writes a commit hash into an
artifact. It never requires a remote, a host, a protected branch, CODEOWNERS, CI, a bot identity
or an installer. Version history belongs to whatever version-control system you use, or to none.

Installation is: copy this folder into your workspace.
